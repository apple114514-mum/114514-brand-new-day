# 周报与研究进展（weekly-report）

导师和组会真正想看的是**结果和卡点**，不是工时流水账。

## 一、素材来源（按优先级）

1. 用户口述 / 本周聊天记录
2. 仓库 git log：`git log --since="7 days ago" --oneline`
3. 本周变更的文件、新增的 `papers/`、`reports/`、`figures/`
4. 上一份周报里的「下周计划」→ 逐条对照是否完成

## 二、输出结构

```markdown
# 周报 2026-W43（10.19–10.25）

## 一、本周完成
- **【结果】** 完成了 XXX 工况的稳态计算，出口温度与实验偏差 3.2%（目标 <5%）
- **【结果】** 复现了文献 [作者, 年] 的失真判据，验证了代码正确性

## 二、遇到的问题
- **现象**：残差在 1e-3 附近震荡不下降
  **已尝试**：加密网格、降低松弛因子
  **现状**：未解决，怀疑边界条件设置
  **需要**：导师确认入口段是否应按充分发展处理

## 三、下周计划
- [ ] 完成 3 个加热功率工况（周一–周三），产出 Nusselt 数对比表
- [ ] 整理开题报告第 2 章初稿（周四–周五）

## 四、需要支持
- 需要 XX 设备/软件权限 / 需要一篇文献的全文
```

## 三、写作原则

- **量化**：不说「跑了一些算例」，说「完成 6 个工况，收敛 5 个」
- **写结果不写过程**：「调了三小时参数」不是成果；「把残差从 1e-3 压到 1e-5」才是
- **问题要具体**：现象 → 已尝试 → 现状 → 需要什么，四句话说完
- **计划要可验收**：写「产出什么」，不写「继续研究」
- 每节 3–5 条，一页为限
- 没完成的计划要说明原因，不悄悄删掉

## 四、保存与交付

- 保存 `reports/weekly-YYYY-Www.md`（如 `reports/weekly-2026-W43.md`）
- 需要 Word 版时用 pandoc 转 docx，保留标题层级
- 汇报用：可再压成 5–8 行要点，供口头讲

## 五、不要做的事

- 不虚构进度（没跑完就写没跑完）
- 不把「学习 XX」当成果，除非有可展示产出
- 不写没有后续动作的「困难」
